# Wheel of Fortune solver

A solver which takes in an empty Wheel Of Fortune board, a category, and then tries to solve the puzzle in as few turns as possible. 

It does this by calculating **probabilities for every letter**, deciding which one to pick, and calculating its confidence in its answers so it can know when to stop guessing letters and solve the puzzle. It uses a small open-weight LLM ([Qwen/Qwen2.5-1.5B](https://huggingface.co/Qwen/Qwen2.5-1.5B)), along with some nuances in order to achieve this.

EXAMPLE:
```
── TURN 3   __A__ _A__ ──────────────────────────────────────────────────────────
called so far: A E R   (not in puzzle: E R)   7 letters hidden
58 candidate answers, entropy 3.06 bits   (4.8s)
top answers  : BLACK JACK 29.8% · SMALL TALK 26.8% · BLACK CATS 8.1% · BLANK WALL 6.6%
P(in puzzle) : L 100%  K 98.6%  B 71.7%  C 63.7%  S 43.7%  T 36.7%  M 31.9%  J 29.8%
solve signal : 0.083  (lower = surer; it guesses at or below the threshold)
=> calls L  (it said 100.0% in puzzle, expected 1.78x)  ...  appears 3x
```

One turn later it solved it: `SMALL TALK`, taking a total of four turns.

## How it works

A language model predicts **tokens** (`" Burt"`, `"aster"`), never single letters, so "what letter
is in slot 7?" is not a question it can answer. So the solver never asks. It makes the model write
**whole answers that fit the spaces (and letters) of the board**, keeps the model's own probability for each, and adds them up:

```
P(letter is in the puzzle) = total probability of the candidate answers that contain it
```

Which letter to call, how sure it is, and when to guess all fall out of that one sum. Each turn, the solver will:

1. **Prompt** the model with a few solved puzzles, then this puzzle's category and current board state.
2. **Filter its tokens** to those that could legally be written at the current board position — a
   blank takes any uncalled letter, a revealed letter takes itself, punctuation must match. 
3. **Search** for the likeliest whole answers that fill the board exactly
4. **Normalize** over the answers found — that's `P(answer | clue, board)`, plain Bayes, no
   re-ranking or hand-tuned features.
5. **Translate** whole words to letter probabilities, and let a policy pick one (default: the most likely letter, then
   switching to whichever best separates the top candidates).
6. **Call it, reveal it, run again** — or guess, once the solver's confidence in its top answer exceeds a certain threshold

The hardest part about solving these puzzles is that there is a huge 'space' of potential words that might be solutions. Of course, we could use infinite compute to try and search through all possibilities, but that's boring. Instead, the solver tries to 'smartly' search for high confidence candidates by:
1. **smart word search** (`wof/slots.py`) when the solver is confident in some words of a puzzle, but unsure about others, it will try and plug in lots of candidate words into the unknown word in order to find the best candidates. This helps the puzzle realize that the best word for the puzzle "A ____ Come True" is "Wish", not "Fish"
2. **a smart judge** (`wof/judge.py`) asks a second model "is this real, familiar English?" to weed out candidates that are nonsense generated by the dumb model's 'simple' token search

[`docs/how-it-works.md`](docs/how-it-works.md) has the full design, the measurements behind each
decision, and what went wrong before it worked.

## Install

Python 3.10+.

```bash
git clone https://github.com/imesh-samarakoon/wheel-of-fortune-solver
cd wheel-of-fortune-solver
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt                        # pulls in PyTorch
python config.py                                       # prints every setting and what's missing
python -m pytest -q                                    # 88 tests, no model or network needed
```

The first solver run downloads the model itself (~3 GB for the 1.5B default) into
`~/.cache/huggingface/`, once.

**On Linux without a GPU, install the CPU-only torch first.** Plain `pip install torch` fetches the
CUDA build and several GB of `nvidia-*` wheels you'll never use; the CPU-only index keeps the whole
environment under 1 GB:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu    # before requirements.txt
```

macOS needs nothing special — its wheel is CPU-only already, and PyTorch uses Apple Silicon's GPU
through `mps` automatically. On an NVIDIA card the default build is the one you want, or pick a
CUDA version from the [selector](https://pytorch.org/get-started/locally/).

**The answer judge** is optional — it needs a [TypeSafe](https://typesafe.ai) API key in
`TYPESAFE_API_KEY`. Without it everything still works; `play.py` prints one note and plays on.

[`docs/setup.md`](docs/setup.md) covers model choices, gated models, measured timings, and download
or judge errors.

## Playing puzzles

```bash
python play.py                        # one of the 101 bundled puzzles, at random
python play.py 42                     # puzzle 42
python play.py "DOUBLE DUTCH"         # by part of its answer
python play.py --list                 # all 101, as boards, no spoilers
python play.py --batch 10 --quiet     # ten puzzles, one line each
```

Adding your own — any answer and category you like:

```bash
python play.py --new                                     # type it in at the prompt
python play.py --answer "A WISH COME TRUE" --category PHRASE
python play.py --called RSTLNE                           # start from a board showing R S T L N E
python play.py --no-fill                                 # skip the expensive fill pass (faster)
```

The solver is told the category and the board, never the answer — the answer only reveals letters
and scores what it believed afterwards. Point `config.PUZZLES_FILE` at your own file to swap the
whole set.

On an ordinary CPU a short puzzle takes about a minute (`BREAK THE ICE`: 62 s, one letter); a long
phrase, several minutes. For something quicker, set `MODEL = "Qwen/Qwen2.5-0.5B"` in `config.py` —
three times faster, and wrong in more interesting ways.

## Reading the code

**Start with [`explore.py`](explore.py)** — one puzzle, every stage printed with real numbers. Run
it cell by cell (VS Code or Cursor: "Run Cell"; or just `python explore.py`): the prompt, how little
of the model's next-token distribution fits the board, the search, each candidate's probability token
by token, the letter probabilities, where the true answer actually sits, how much the search missed,
and the whole puzzle played out.

**[`config.py`](config.py) is the only place with settings** — model, search width, calling policy,
when to guess, whether the judge is on. Each says what it does and what the interesting alternatives
are; both scripts read it. Good first changes: `MODEL`, `POLICY`, `SOLVE_AT`, and `CASE` (set it to
`None` to watch the model start copying the board in capitals).

```
play.py              play a bundled or your own puzzle
explore.py           the walkthrough: one puzzle, every step printed
config.py            every setting, plus a setup check
wof/
  board.py           what's showing, what's been called, what still fits
  search.py          the model, searched token by token under the board's constraint (the core)
  posterior.py       candidate answers -> per-slot and per-letter probabilities
  policy.py          which letter to call
  calling.py         play a whole puzzle, one letter at a time
  slots.py           filling one open word from a word list
  judge.py           a second model's opinion: real English, or board-fitting junk?
  adjust.py          how much of the model's probability the search actually found
  puzzles.py         the puzzle file and the prompt examples
  show.py            every printout
data/puzzles.json    101 puzzles to play + 208 kept aside as prompt examples
data/words.txt       43,653 common English words, for filling a single open board word
tests/               88 tests, no model needed
```

## Caveats

The bundled puzzles are **hand-written** in the show's style, not the show's archive — they aren't a
benchmark. Any model trained on the web has already read these phrases, so a good result means "the
model knows this phrase and the search found it", not anything about the show. Nothing is tuned per
puzzle: every setting is global, chosen on a small number of puzzles.
